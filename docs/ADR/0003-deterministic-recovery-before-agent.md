# ADR-0003: 确定性恢复优先，Agent 作为受限升级路径

- Status: Accepted
- Date: 2026-10-15

## Context

页面加载失败、无响应、renderer 崩溃或结构变化后，普通 userscript 可能已经无法运行。产品还需要 Agent 处理未见过的页面，但模型调用具有延迟、成本、不确定性和权限风险。

仅靠截图无法判断业务是否已经完成，也无法阻止重复提交或重复下载。仅靠 Agent 维持浏览器存活，也会形成单点依赖。

## Decision

恢复顺序固定为：

1. 页面与业务健康探针判断状态。
2. 短暂失败等待并退避。
3. reload 或忽略缓存 reload。
4. 按允许范围清缓存和站点存储。
5. 销毁并重建 `WebContentsView`，恢复最近检查点。
6. 子进程连续异常时受控重启应用。
7. Electron main process 失联时由独立 Watchdog 重启。
8. 确定性规则无法识别的新状态才升级给 Agent 或人工。

每个 workflow 步骤必须声明前置条件、成功断言、超时、幂等键、重试预算和失败转移。关键检查点必须持久化，不能只保存在 renderer 或 Agent 会话中。

Agent 只能调用经过校验的高层浏览器工具，例如观察、点击、输入、导航、等待、断言和恢复。Agent 不获得 shell、原始 IPC、密钥或任意文件访问。

## Consequences

正面影响：

- Agent 不可用时，浏览器监督与已知流程仍能继续工作。
- 恢复行为可以测试、审计和复现。
- 幂等键减少重复提交、下载和其他业务副作用。
- 高风险行为可以统一审批和熔断。

代价：

- 需要为业务状态和成功条件投入显式建模。
- 录制得到的操作不能直接视为可运行 workflow，必须补充断言和恢复边。
- Agent 能力会受到工具层约束，不能任意“接管电脑”。

## Rejected alternatives

- Agent-first 自动化：成本和不确定性过高，不适合作为运行时基础。
- 纯脚本重试：页面脚本失效后没有外部恢复能力。
- 固定延时录制回放：无法适应网络延迟、页面变化和重复副作用。
